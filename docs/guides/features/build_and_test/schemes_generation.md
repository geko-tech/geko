# Schemes generation

Geko can automatically generate schemes for your workspaces and projects. This section describes the available options for the [`autogeneratedSchemes`](../../../projectdescription/structs/Workspace.GenerationOptions.md#autogeneratedschemes) parameter of the `Workspace` manifest.

## Workspace

Generate a workspace scheme that includes all available targets and test targets:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .workspace(
            platform: .iOS,
            // ...
        ),
    ],
)
```

### `suffix` parameter

You can create several different workspace schemes, but to avoid name collisions you need to add a suffix to the scheme name:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .workspace(
            platform: .iOS,
            suffix: "SchemeSuffix1"
            // ...
        ),
        .workspace(
            platform: .iOS,
            suffix: "SchemeSuffix2"
            // ...
        ),
    ],
)
```

### `onlyFocusedTargets` parameter

If `onlyFocusedTargets: true` is set, the scheme will include only the targets that are in the focus.

If `onlyFocusedTargets: false` is set, the scheme will include all available targets from all projects that have at least one target in the focus (for example, extensions of the main application or targets with resources).

By default the parameter is `true`.

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .workspace(
            platform: .iOS,
            onlyFocusedTargets: true
            // ...
        ),
    ],
)
```

### `productFilters` parameter

This parameter filters targets by the passed array of `Product` values. By default it is an empty array, which means all targets are included.

For example, if you only want to build frameworks and static frameworks. This can be useful when you don't need to build test targets and the main application target:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .workspace(
            platform: .iOS,
            productFilters: [.framework, .staticFramework],
            suffix: "Frameworks"
        ),
    ],
)
```

For example, if you only want to build apps:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .workspace(
            platform: .iOS,
            productFilters: [.app],
            suffix: "Apps"
        ),
    ],
)
```

## Projects

Generate schemes for all projects:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .allProjects(
            targetSchemesGrouping: .singleScheme
            // ...
        )
    ],
)
```

Generate a scheme for a specific project. When used together with `.allProjects`, it overrides the scheme for the specified project; to avoid overriding, you can set the `suffix` parameter on the scheme name:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .project(
            name: "MainApp",
            // suffix: "SchemeSuffix",
            targetSchemesGrouping: .singleScheme
            // ...
        )
    ],
)
```

### `targetSchemesGrouping` parameter

Controls how schemes are grouped for a project. See the [`AutogeneratedSchemeProject.TargetSchemesGrouping`](../../../projectdescription/enums/AutogeneratedSchemeProject.TargetSchemesGrouping.md) documentation for the full list of cases:

* `.singleScheme` – generate a single scheme for each project.
* `.byNameSuffix(build:test:run:)` – group schemes according to the suffix of their names.
* `.pods` – group the targets by local pods. 1 build+test (required), n app (optional).
* `.notGrouped` – generate a scheme for each target.

For example, to generate a separate scheme for each target:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .allProjects(
            targetSchemesGrouping: .notGrouped
            // ...
        )
    ],
)
```

### `suffix` parameter

To avoid name collisions, you can use the `suffix` parameter to add a suffix to the scheme name:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .allProjects(
            suffix: "AllProjectsSchemeSuffix",
            targetSchemesGrouping: .singleScheme
            // ...
        ),
        .project(
            name: "MainApp",
            suffix: "SchemeSuffix",
            targetSchemesGrouping: .singleScheme
            // ...
        )
    ],
)
```

### `onlyFocusedTargets` parameter

If `onlyFocusedTargets: true` is set, the scheme will include only the targets that are in the focus.

If `onlyFocusedTargets: false` is set, the scheme will include all available targets from all projects that have at least one target in the focus (for example, extensions of the main application or targets with resources).

By default the parameter is `true`.

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .allProjects(
            onlyFocusedTargets: true,
            targetSchemesGrouping: .singleScheme
            // ...
        ),
        .project(
            name: "MainApp",
            onlyFocusedTargets: true,
            targetSchemesGrouping: .singleScheme
            // ...
        )
    ],
)
```

### `exceptRegexps` parameter

You can exclude scheme generation for targets by a regular expression, for example for mock and resource targets:

```swift
generationOptions: .options(
    autogeneratedSchemes: [
        .allProjects(
            exceptRegexps: [".*Mock$", ".*Resources$"],
            targetSchemesGrouping: .singleScheme
            // ...
        ),
        .project(
            name: "MainApp",
            exceptRegexps: [".*Mock$", ".*Resources$"],
            targetSchemesGrouping: .singleScheme
            // ...
        )
    ],
)
```
